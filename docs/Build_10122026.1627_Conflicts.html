Conflicts and decisions

RESOLVED · EMPTY SCENES

The previous schema required a panel in every scene

Moving all panels out of a scene conflicted with that rule. Scenes may now be empty, are kept in the project, and display a target for dropping panels back into them. The project still requires at least one panel overall. Existing project IDs and the format identifier are preserved.

The old developer build cannot read a new document containing empty scenes. Use this Version 1 build for those documents; no data migration is needed to open earlier files here.

SAFEGUARD · CAMERA-KEYED SCENES

Panel transfers can change the meaning of scene-owned camera timing

Moving individual panels into or out of scenes with camera keys is blocked. Moving the whole scene is allowed and preserves the camera track. A duration reduction that would leave a key outside its scene is also rejected. This protects authored data until the camera retiming interface is available.

Attention: Panel transfers and duration changes work for ordinary projects. Existing camera-keyed scenes need the later camera-retiming milestone before individual panel transfers can be supported safely.
RESOLVED · FILE COMPATIBILITY

Changing extensions must not strand earlier projects

Open accepts .issb and .innovent. Browser exports use .issb. Desktop Save offers a new .issb copy for earlier-extension files and leaves the earlier file unchanged. Internal recovery filenames remain compatible with the earlier developer build. The application name change preserves the desktop data directory.

RESOLVED · VERSION VS. PACKAGE FORMAT

A human Version 1 and date-stamped build are separate from package semver

The UI, About information, documentation, build metadata, and archive use the exact requested Version 1 / Build 10122026.1627. Package tooling uses 1.0.0 as its required semantic version. The date stamp is stored separately, rather than being treated as a minor or major release. The build-update script changes the major version only when explicitly given a major-release option.

RESOLVED · TIME PRECISION

Time editing must remain aligned with a frame-based storyboard

Time in seconds is the default; Frames is a preference. Decimal seconds are rounded to the nearest project frame, with the resulting value shown after editing. Timing remains one shared value in all workspaces. Timeline widths represent timing; Drawing and Panel card widths remain fixed.

RESOLVED · REPEATED PANEL NAMES

Cross-scene moves can introduce two panels named “Panel 3”

Panel IDs remain unique. Names are preserved rather than renamed silently. Destination choices show current positions, and card tooltips identify their scene and position. This distinguishes repeated names without changing dialogue, layer names, or other authored text.

FIXED · INTERACTION BUGS

Drop markers and timeline layout needed targeted corrections

Scene markers now accept pointer events only during a scene drag, so they do not intercept ordering buttons. Short windows scroll the timeline instead of clipping controls. Timeline duration captions render on their own line instead of flowing beside the preview image. Cancelled resize gestures make no project change, and a completed gesture is one undo step.
