Quick start

  1. Open Timeline. Click Import audio and choose one or several files. With no track selected, each file creates its own track at the current playhead time.
  2. Select a track to import more clips into it, or click New-track imports to return to separate-track imports. + Audio track adds an empty track.
  3. Drag a clip body to move it, including between rows. Drag its edges to trim. Arrow keys move a focused clip by one frame; Shift adjusts by ten frames.
  4. Select a clip to edit start, source in, duration, destination track, name, and volume in the existing properties panel. Times follow the application’s time/frames preference.
  5. Use each track’s M/S buttons and volume control to audition the mix. Multiple solo tracks can play together; mute takes priority.
  6. Use the usual playback controls in Drawing, Timeline, or Pitch. Timeline scrubbing seeks picture; resumed playback starts sound at the matching source position.
  7. Click Export animatic in Timeline. Keep the application visible while the WebM records in real time; Cancel stops the export without a partial download.

Timing and portability rules

RuleBehavior
Audio positionClips use absolute project-frame positions. Panel duration changes, reorders, and transitions do not automatically move audio.
Project endStoryboard panel timing determines playback/export length. Audio extending beyond that end is shown with a notice and is cut at the project end. Extend panel timing to include its tail.
Trim/sourceEdits change source offsets and durations; original embedded bytes remain intact. Duplicate clips share the same asset. Unreferenced assets are removed after clip/track deletion and restored by Undo.
Project transferCopy the .issb file; no separate media folder or relinking is required. Original audio is embedded rather than referenced by external paths.
Browser recoveryProject history/recovery now uses IndexedDB to accommodate audio projects larger than the old localStorage quota. Legacy browser records are still readable. Native desktop saves retain their existing atomic file-writing path.

Compatibility and limits

New saves use schema 4. Existing schema 1/2/3 files upgrade in memory and are not changed until Save. Older builds reject schema 4 projects rather than silently losing audio. Preserve earlier copies before testing a full build rollback. The Classic/Updated icon preference remains available within this build.
