## R1.4-A — Distribution policy (documented)

- Use isolated `R1.4-Private-Distribution-Readiness` based on `Release`; validate changes there before an explicitly authorized merge into `Release`, then separately synchronize `main`. No independent parallel edits to protected branches.
- No Apple Developer Program membership or Developer ID certificate is available. Developer ID signing and Apple notarization are **deferred**, not completed. Existing ad-hoc signing may be used for controlled testing but is not an identity assertion or a notarization substitute.
- Recipients must be informed that macOS Gatekeeper may warn or block an unnotarized downloaded application. Provide only Apple-supported per-app user-initiated review/open steps; never instruct recipients to disable Gatekeeper/SIP globally or strip quarantine broadly.
- Distribute only through an access-controlled channel to named, authorized recipients; provide integrity hashes and instructions to verify the installer before opening. No release assets are published by this checkpoint.
- Reassess signing/notarization and distribution controls before any audience expansion or public release. Noncommercial/private status does not waive third-party license conditions.
- Final package publication requires explicit owner authorization after the remaining gates pass.
